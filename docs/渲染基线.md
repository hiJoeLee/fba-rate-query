## 为什么这几项必须实测、不能推算

`td.ov`（长文本气泡标记）与 `data-full` 单元格数是**真实布局测量**的结果：页端对每个
`td[data-full]` 里的 `.cl` 做两行截断判定，**溢出**才加上 `ov` 类与点击气泡。
溢不溢出取决于字体度量 × 列宽 × 内容长度，**没有任何命令行方式能算出来** ——
`tools/current_numbers.py` 能给你列宽与内容，给不出"会不会溢出"。所以：

- 改过 **列数 / 列宽 / 单元格内容 / 字体** 之后，**必须按下面的方法重测一次**，并在下表追加一行。
- **不要用「预期不增」代替实测。** 2026-09-19 那次就是只在文档里写了"预期不增"、没测 ——
  这种断言等于没有断言，只是把未知包装成已知。

## 怎么测

1. **本地文件必须先用 HTTP 打开**（`file://` 下部分测量与 `requestIdleCallback` 行为不同）：
   ```bash
   cd ~/Documents/trae_projects/fba-rate-query && python3 -m http.server 8899
   ```
2. 浏览器打开 `http://localhost:8899/index.html`，**全部分组展开**（点「展开全部」；
   页端对分组数/行数有自动展开上限，需手动展开到位）。
3. 打开 DevTools 控制台，粘这一段（只读，不改页面）：
   ```js
   const tds = [...document.querySelectorAll('#list td[data-full]')];
   console.log(JSON.stringify({
     分组数: document.querySelectorAll('#list tbody').length,
     行数: document.querySelectorAll('#list tbody tr').length,
     dataFull: tds.length,
     tdOv: tds.filter(td => td.classList.contains('ov')).length,
     信息列合计: TBL_INFO_COLS.reduce((s, [, w]) => s + w, 0),
     列数: TBL_INFO_COLS.length,
   }));
   ```
4. 把输出连同**当次数据规模**（`python3 ../fba-rate-parser/tools/current_numbers.py` 的
   「记录 / 分组 / 列数 / 合计宽度」几行）一起记到下表。
