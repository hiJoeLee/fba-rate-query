## 近期决策

- **`tools/chat_query.py` 入库：修三个「静默少给」缺陷 + 补 README 导航（2026-09-25，用户要求「提交入库并更新 README 导航」）**
  - **背景**：该脚本自 2026-09-19 起就存在于工作区，但**从未入库、未被 `.gitignore` 忽略、全项目文档零引用** —— 属于「悬空资产」。本次把它固化为仓库资产（与解析端 `tools/README.md` 开头那句同因：「原先只存在于会话临时目录，不入库、不跨会话留存，每次并表都要重新摸索一遍」）。
  - **入库前先复核它的真实行为，抓到三个缺陷（都在"静默"这一类）**：
    1. **`limit` 完全无效** —— `query()` 收下但不使用，`report()` 用自己的默认 10；CLI 传 `limit=2` 实测仍出 7 行。已修：`limit` 移出 `query()`（它是展示参数不是过滤参数），在 `__main__` 里取出并传入 `report()`。
    2. **`重量档` 是死参数** —— 签名里有、函数体里从未使用 → 传了**静默无效**。已实现为「只保留 `价格` 里含该档位名的记录」。
    3. **归并会吞记录** —— `report()` 按**渠道名称**去重，实测有 **2 个**渠道名同时存在于皓鹏的两张表（`美国包税_美森加班卡派限时达` / `美国包税_美森正班卡派限时达`，分别在「美森以星合德OA非OA海卡」与「美西美东商私卡」）→ **只显示其中一张表的价，另一张静默消失**。已改为按 `供应商代码 / 来源表名 / 渠道名称 × 单位 × 区间` 归并。
  - **顺带查出的更深一层问题（也是归并键的由来）**：同一渠道名会**跨区间/跨单位**（实测 **50 组**跨区间、且**单位会分叉**，即有 KG 又有 CBM）→ 只按渠道名归并会**少给一半的价**；即使进了「单位×区间」，同组的 `价格` 仍会因**邮编段 / 时效**分叉（实测 **337/389 组**不一致）→ 故逐档位取 `最小~最大` 而不是只取第一条。
  - **防回归**：`report()` 内加 `assert` 断言**归并前后条数相等**（防的正是"静默少给"）；未知参数**直接报错**（`query()` 的 `TypeError` 被捕获后 `sys.exit`），不再静默忽略。
  - **价格格式对齐页端**：改用与页端 `fmtPrice()` **同口径**的 `fmt_price()`（整数带千分位、非整数留 2 位去尾零 → `8.51096022241232` 显示为 `8.51`，与页面一致）。页端 `title` 里的精确值（`fmtFull()`）不打印，已在 docstring 写明。**`__FBA_MARKUP__` 不参与** —— 只回成本价。
  - **[验证]**：11 个参数逐个验证**命中数均发生变化**（证明真起作用）；参数**组合穷举 66 组**，逐组断言 Σ组内条数 == 命中数 → **丢记录 0 组**；两个跨表同名渠道的报告里**两张表都出现**；`fmt_price` 六个取值与页端口径一致；空命中不误触发断言。
  - **文档**：`README.md` 与 `docs/README.md` 各补 `tools/` 导航；`docs/README.md` 新增「tools/ 辅助脚本（只读）」一节（参数表 + 两条归并纪律 + 价格格式）；顺带订正 `docs/README.md`「本仓库内容」里把 `DECISION_LOG.md` 写成根目录的旧错（实际在 `docs/`）。另：**本轮只改 `tools/` 与文档，`index.html` 一字未动**。

- **「渠道说明」加兜底：整表不得静默无说明（2026-09-24，用户发现「扬程 墨西哥海运快线」没有渠道说明）**
