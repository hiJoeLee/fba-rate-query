## 近期决策

- **新增「邮编查询」筛选条件（9/11）**：落地此前建议的「输入客户邮编 → 自动命中对应区间」。判定**直接取自解析端协议 §5.9.3**，不另造口径：
  - **命中式**：`int(开始邮编) ≤ int(客户邮编) ≤ int(结束邮编)`（闭区间）。
  - **按位数识别国家**：5 位=美国、4 位=澳大利亚；位宽正源 = 解析端 `sheet_configs.ZIP_WIDTH`。**位数与该国不符 → 不命中**。这一条是必需的：澳洲邮编 `2000` 的数值恰好落在美国 `00000-39999` 区间内，若只做数值比较会**跨国家误命中**。
  - **无邮编区间的记录 → 不参与命中**（按协议「不要当成 0」）。因此该条件是**严格口径**：只留 60 条按邮编分档的记录（美国 36 + 澳大利亚 24），其余 **2936 条（全国统一价、不按邮编分档）会被一并过滤掉**——输入一个美国邮编后只剩 `美国空运` 与 `美森以星合德OA非OA海派` 两张表。若日后要「不分区间的表也一并列出」（它们其实覆盖全境），需另加开关；已在 README 标注。
  - **交互**：输入只留数字、最多 5 位；下方实时提示识别到的国家（`按「美国」5 位匹配邮编区间`），非 4/5 位标红 `需 4 位或 5 位数字`；已纳入 `activeCount`（9 个筛选项）与「重置筛选」。
  - **功能测试（不只做静态校验）**：把页面里那段 `ZIP_WIDTH`/`zipHit` **原样抽出**、喂真实数据在 node 里跑：`20000` → 美国 12 条（海派 R10 ×8 + 美国空运 R11 ×4，即 `00000-39999`）；`99999` / `96815` → 美国 12 条（`80000-99999`）；`2000` → 澳大利亚 4 条（悉尼 `1000-2999`）；`123` / `123456` → 0 条且识别国家为空 ✓。
  - 验证：`git diff` 仅这 8 处（×2 文件）；**数据行逐字未变**（仍 2996 条）；两文件逐字节一致；整体内联 script 过 `node --check`。
- **修「字段变长导致表格背景断裂」（9/11）**：上一条把信息列由 8 列扩到 12 列后，用户反馈「背景有点问题」。根因是**表格总宽超过容器宽度**——`.wrap` 内容宽上限 1280px，而 `.tbl-scroll` **只在手机断点（≤640px）才有 `overflow:auto`**：
  - 改前：信息列 908 + 6 档×60 = **1268** ≤ 1280（只有 12px 余量，恰好塞得下）
  - 改后：1240 + 360 = **1600** → **表格溢出容器 320px**
  溢出的右侧价格列落在容器外，**容器的白底/边框/圆角只铺到容器宽度**，那一截就透出页面底色。用户看到的正是这个；改前那 12px 余量本来就是巧合，不是设计余量。
  - **修法**：把手机端已有的「容器可滚动」提到**基础样式**（`.tbl-scroll{overflow:auto;-webkit-overflow-scrolling:touch;max-height:70vh}`），表头 `top` 由 `calc(12px + var(--fb-h,0px))` 改为 `0`；并把明显偏宽的列收紧（信息列合计 **1240 → 1068**），使 **1–3 档的分组无需横滑**，4/5/6 档分别只差 30/90/150px。手机断点里那两条重复定义随之删除。
  - **行为变化（唯一一处）**：桌面端长表格由「整页滚动 + 表头吸在筛选栏下方」改为「**容器内滚动 + 表头吸在容器顶部**」。这是让表格能横滑的必然代价——`overflow:auto` 必然让元素成为滚动口，而 sticky 只相对**最近的滚动口**生效，视口吸顶不可能保留。**权衡**：容器内滚动只作用于已展开的分组（默认全部收起，展开即聚焦），观感接近；换来的是「不会再破底」这一硬保证——不管以后加多少列、多少档位。另一条路是按宽度断点切换（≥1320px 回到原行为），但那要求信息列压到 918px 以内，12 列会被挤成两行换行、可读性明显下降，故未采用。
  - **宽度预算已写入 README**：`信息列合计 + 档位数×60 + 2（边框）≤ 1280` 才免横滑。**加列/加档位前先算这笔账**。
  - 验证：`git diff` 仅这 5 处（×2 文件）；**数据行逐字未变**（仍 2996 条）；两文件逐字节一致；内联 script 过 `node --check`；信息列合计 1068 与各档位所需宽度已复算（1/2/3 档放得下，4/5/6 档缺 30/90/150px）。

## 踩坑点

- **多文件同步**：三处结构一致的页面（`index.html`、`fba-rate-query.html`、`/tmp/fba_page_template.html`）必须逐字节一致。任何一处漏改都会造成线上「改了没生效」。每步提交前用 `diff fba-rate-query.html index.html` 校验。
- **推送超时**：直连 GitHub 时常 `Recv failure: Operation timed out`。用 `/Users/Zhuanz1/git-push.sh` 触发，或先确认 Clash 在 `127.0.0.1:7897` 监听。
- **计费单位易混**：`单位` 存的是 `KG` / `CBM`（不带「元/」）。按体积计费的 `CBM` 记录不能按 KG 直接查，否则比价会错。
- **两套筛选口径**：`运输方式` 是 `干线/末端` 拼接（如 `空运/快递派`），前端拆成两段独立筛选；`渠道名称` 是更完整的拼接，两者不等价。
