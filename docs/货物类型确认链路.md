# 货物类型确认链路（客户自助 → 建议 → 市场确认）

> 更新：2026-10-03 · 范围：运费计算页（feat/计费）· 状态：MVP 已实现，市场确认后回补

## 一、问题

FBA 报价中，货物类型（普货 / 带电敏感 / 一类~四类 / 墨西哥 A/B/C）决定：

- 哪些渠道**可以走**（渠道按货型收件）；
- 哪些**附加费**被触发（带电费、超重费、偏远费等）。

但"墨西哥 B 类"、"三类"是**供应商内部分类口径**，客户发货时不知道自己的货属于哪类，让客户直接选必选错。选错不只是金额偏差：带电货选了普货会匹配到不收带电的渠道，货到目的港被扣/补费。

## 二、设计原则

前端不产出任何"权威分类结论"，只做**建议 + 客户自选**，权威口径永远在市场和业务确认侧。这样前端词典再怎么猜，都不会污染报价准确性；市场永远有纠错权。

## 三、三层分工

| 层 | 谁 | 做什么 | 边界 |
|---|---|---|---|
| 客户自助 | 客户 | 填货物名称（选填）、选货物类型、填货物信息，点计算 | 类型永远由客户**自己选定**，页面明示"分类由客户确认，可能影响匹配与实际报价" |
| 建议层 | 前端 | 名称 → 关键词词典 → 给分类建议（带"采用"按钮） | 词典是轻量版（源自供应商价格表说明），**不产出权威结论**；未命中不硬猜 |
| 市场确认 | 市场/业务 | 客户咨询时按供应商渠道规则人工校正，给准确报价；后台维护分类映射词典与确认口径 | 前端留好提示与"需单询/待确认"闸门，市场回补后自动解锁 |

## 四、页面实现（现状）

- 输入：`c_gname`（货物名称，选填）+ `c_type`（货物类型下拉，按目的国联动）
- 建议位：`c_gname_hint`（货物名称下方小字）
  - 命中：`建议选择「X」：说明 <采用>`，点采用即填入货物类型；
  - 未命中：`未收录该货物分类，请先咨询业务确认后再选择`；
  - 类型说明：`c_type_note` 显示该分类的供应商定义 + 尾部固定提示"分类由客户确认，可能影响匹配与实际报价"。
- 词典：
  - `TYPE_HINTS`：按国家分组的专属分类关键词（巴西 一类~四类、墨西哥 A/B/C）；
  - `TYPE_HINTS_COMMON`：通用分类（普货、纺织品）；
  - `TYPE_HINTS_SENS`：带电/敏感风险词（电池、充电宝、磁铁、液体等）。
- 匹配顺序（`suggestType`）：**带电/敏感风险词优先（警告）→ 目的国专属 → 通用**。

## 五、混装（多名称）规则

FBA 一票货常混多 SKU。`c_gname` 支持逗号/顿号分隔多名称（如 `手机壳,数据线,充电宝`）：

1. 逐词匹配，收集全部命中分类；
2. **任一命中带电/敏感 → 整体按「带电/敏感」警告**（风险最高，最严格口径优先）；
3. 命中多分类 → 列出全部建议 + 提示"混装建议按最高类别申报，实际以业务确认为准"，客户自行选定（不强制采用哪个）；
4. 全部未命中 → "未收录，请咨询业务"。

## 六、与后端 B 阶段的关系（市场确认后回补）

| 事项 | 现状 | 后端 B 阶段 |
|---|---|---|
| 分类映射词典 | 前端内嵌轻量版（`TYPE_HINTS*`） | 入库，运营后台维护"货物名称 → 分类"，前端运行时拉取 |
| 分类说明 | 前端内嵌 `TYPE_NOTE`（源自原始价格表） | 随渠道数据下发，后台可编辑 |
| 待确认费用 | `param_pending` / `manual_check` 触发"需单询/待确认"（61 条规则闸门） | 市场确认后解锁为可计算 |
| 权威报价 | 无（前端不产出） | 市场确认口径持久化，报价记录可追溯 |

## 七、市场需要维护什么（确认单待回收）

1. **分类映射词典**：常见货物名称 → 分类的完整映射（前端轻量版只是起步，市场按实际咨询积累补充）；
2. **确认口径**：混装一票多类的申报规则（按最高类别 / 按主货 / 按占比）——前端暂以"最严格"提示；
3. **manual_check 清单**：26 条待人工确认的附加费规则逐条复核回填。

## 八、验收基线

- 墨西哥 + "手机壳" → 建议「墨西哥A类」；巴西 + "衣服" → 「四类」；"充电宝" → 带电警告；未知词 → 咨询业务提示；
- 混装 "手机壳,充电宝" → 带电警告；"手机壳,数据线" → 多分类建议；
- 重置按钮清空名称与建议；
- 计算金额不受名称影响（名称只做建议，不进求值器）。
