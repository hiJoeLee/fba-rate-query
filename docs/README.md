# FBA 运价查询台

供应商 FBA 运价表拆解结果的查询页面（纯静态单文件）。

- **线上网址**：https://hijoelee.github.io/fba-rate-query/
- **数据源**：fba-rate-parser 拆解输出（**规模随每次并表变化 —— 要当前值跑 `tools/current_numbers.py`，本文件不登记**）
- **技术**：单文件 HTML + 内嵌 JSON，零依赖、免后端、免登录、手机自适应
- **部署**：GitHub Pages（推送 `main` 分支自动部署，免费无次数限制）

## 数据概览

当前数据集字段：`文件 / 来源表名 / 来源行号 / 供应商代码 / 渠道名称 / 运输方式 / 交货地 / 交货仓库 / 可收货城市 / FBA仓库 / 时效 / 船期 / 体积重量比 / 货柜容量 / 开始时间 / 货币 / 货物类型 / 国家 / 城市 / 开始邮编 / 结束邮编 / 是否包税 / 单位 / 区间 / 价格`（25 字段）。

**三家供应商（2026-09-11 起为多供应商，9/17 并入扬程）**：皓鹏（美系海卡为主）/ 蓝图梦（美国海运）/
扬程（美加墨专线）。**每家多少张表、多少条记录、多少个渠道 —— 本文件不登记**（每并一张表就变）：
```bash
cd ../fba-rate-parser && python3 tools/current_numbers.py
```
> 记录数口径：**页端条数少于解析端单价点数** —— 页端粒度为「渠道 × 行 × 区间」（`价格` 是重量档 dict），一条记录承载多个单价点。两者都由上面那条命令给出。

**字段持有（哪些字段是"窄字段"）**：`船期`、`开始邮编`/`结束邮编`、`城市` 都是**少数表才有值**的
字段（例如 `城市` 当前只有 `澳大利亚空海` 带），`体积重量比` 只随 KG 记录出现，`货柜容量` 非全量持有。
**具体条数随数据变，要当前值跑上面那条命令**；下表只保留**口径**，不保留条数。

**字段口径（含已清理的历史遗留）**：

- `货柜容量`：整柜容量（CBM），现为数字 `68`（正源 = 解析端 `sheet_configs.CONTAINER_CBM`）。历史上这里存的是 `"1900-03-08"`——Excel 把 `68` 当日期序列号误存，**已于 9/10 修正 413 条**。前端不使用该字段（数据块之外 0 处引用）。**非全量持有**：缺值集中在 `英国空卡铁海` 与 `澳大利亚空海` 两张表（持有不一致，**未处理**）；蓝图梦与扬程的表是全带。**当前缺多少条由命令现算**。
  - **同一件事在「字段口径」（本节）与「字段字典」里各写了一遍** —— 这不是重复，是分工：本节讲**为什么这么定**（口径与历史遗留），字段字典讲**字段是什么**（类型/示例/取值）。改口径时**两处都要看**。
- `体积重量比`：**KG 记录填 `167`、CBM 记录不带该键**（前端渲染「重比 1:167」）。该口径**已两端统一**——9/10 裁定以页面为准，解析端改为「KG→167 / CBM→空」。`167` 对应源表空运口径「长cm × 宽cm × 高cm / 6000」。
- `时效`/`运输方式`：解析端存原始派送方式（如 `DPD派`）与空时效，页面入页时补全为 `干线/末端`（如 `空运/快递派`）并回填源表的时效说明。**入页不是纯机械转换**，新表并入时需按此补全。
- `开始邮编`/`结束邮编`：**区间对**，**字符串类型**，按国家位宽左侧补零（美国 5 / 澳大利亚 4；正源 = 解析端 `sheet_configs.ZIP_WIDTH`）。二者构成**闭区间**，消费端命中判定为 `int(开始邮编) ≤ int(客户邮编) ≤ int(结束邮编)`。**有值的是少数表**（当前为 `澳大利亚空海` / `美森以星合德OA非OA海派` / `美国空运` / `全美快递派`；**条数随数据变，不在文档登记**）。其余记录为空串（或本就不带该键），表示**不按邮编分档**，不参与邮编命中，**不要当成 `0`**。
  - **来源已收口到解析端（9/11）**：澳大利亚那批原是本页手工补录的，现已确认**源表 `澳大利亚空海!U9:U14` 本就写着**「城市 + 邮编区间」（`悉尼\n1000-2999` 等），解析端已改为从源表产出。本页这 48 组「渠道 × 行 × 区间 × FBA仓库 × 城市 × 邮编」与解析端**逐条完全一致**，**本页数据未改动**（原先补录的值就是对的）。解析端现为该字段正源，后续新增澳洲表不必再手工补。
  - **9/11 之前这里存的是数字**（`1000`），已统一迁移为字符串（`"1000"`）——两端口径一致。**不能用数字存**：美国 `00000` 会退化成 `0`，前导零丢失；且 JS 里 `'00000' <= 20000` 会退化成字符串比较，结果错误。完整口径（含位宽表、双源形态、美国三段区间、连续列表前提）见解析端协议 §5.9。

- 记录数、来源表数、供应商数、各供应商条数 → **跑 `tools/current_numbers.py`**（随每次并表变化）
- 来源表去重口径：皓鹏与扬程各有同名「美国空运」，故**页上表数少于三家登记表数之和**；身份消歧靠复合键 `供应商│来源表名`
- 目的地国家：扬程只覆盖美/加/墨三个既有国家，未引入新国家
- 计费单位 **3** 类：KG / CBM / **件**（本体 CBM 的是体积计费，不能按 KG 直接查；`件` 仅 `美国空运小货特快` 的「小货特快专线」，不可按重量套用）
- 货币 **2** 种：RMB / USD（USD 仅 `巴西海运`）

> **页面体积**：单文件 = 页面代码 + 内嵌 JSON（数据仍内嵌，保留「免后端、可离线打开」前提）。**当前值跑 `python3 ../fba-rate-parser/tools/current_numbers.py`**（会打印页文件字节数与数据行字节数）。**体积路线 9/17 已裁定：不优化、直接并入** —— 内嵌 JSON 在 GitHub Pages 传输时仍会 gzip（下载体积约为原始的 1/4），用户可接受；代价是仓库体积与 git 历史变重，**每次月度重传都按此量级累加**。**9/16 已完成性能优化**（详见下节「渲染性能」）。

**税制口径**：源表未明确写「包税 / 不包税」的，一律按**包税**处理（美系海卡的 KG 档即属此列）；渠道名按税制拆为 `美国包税_…`（KG）/ `美国不包税_…`（CBM）。英国、澳大利亚源表本身有税制明文，不受默认值影响。**加拿大空海**仅直航两块有明文（其余 9 块默认包税）、**美国空运**全表无明文（276 条全默认包税）、**欧洲空卡铁海**全表无明文（249 条全默认包税，渠道名前缀 `欧洲包税_…`）。完整法则见解析端 `fba-rate-parser/docs/报价表_读取协议_模板.md` §5.6。

**运输方式取值**（`干线/末端`，前端拆成 head/tail 两段筛选）：**词汇表（结构性，条数不登记）** —— `海运/卡派`（最多）、`海运/铁路`（纽约海铁，9/17 用户裁定新增）、`海运/快递派`、`空运/卡派`、`空运`（无末端）、`海运`（无末端）、`空运/快递派`、`空运/UPS派`、`空运/直送`、`海运/直送`、`铁路`（无末端）、`海运/UPS派`、`铁路/卡派`、`卡航`（无末端）、`铁路/直送`、`卡航/卡派`、`卡航/直送`、`铁路/快递派`、`卡航/快递派`。`海运/UPS派`、`空运/UPS派` 来自**加拿大空海**与皓鹏**美国空运**（源表末端写 UPS派）。**干线取值 4 种**（卡航 / 海运 / 空运 / 铁路）、**末端取值 6 种含空串**（空 / UPS派 / 卡派 / 快递派 / 直送 / 铁路）。**要当前各取值的条数**跑 `tools/current_numbers.py` 或直接看页面筛选下拉的选项数。
> **末端的两种缺省不是同一回事**：`海运/卡派` 等的末端是源表明写的派送方式；而 `空运`/`海运`/`卡航`/`铁路` 四种**没有末端**，源表该行只标了干线（欧洲表的「直送」行则在 `运输方式` 第二位写 `直送`）。前端 `splitMode` 对无末端的写法**原样返回空串**——**9/11 修**：旧式 `(b||'').replace(/派$/,'')+'派'` 会把无末端补成 `派`、把 `直送` 补成 `直送派`（都不是真实术语），已改为恒等解析（对存量 2996 条是严格无操作，因为它们的末端本就都以「派」结尾；此后新增的 168 条裸头程因此得到**空末端**而非假 `派`）。

## 字段字典

每一条记录代表「某个来源表里、某一计费区间段下、某个渠道的一个订单行」，对应的单价档位放在 `价格` 对象里。

| 字段 | 含义 | 取值示例 |
|---|---|---|
| `文件` | 数据批次 / 来源 Excel 文件名标识 | `皓鹏国际同行vip8月31日` |
| `来源表名` | 源表 Sheet 名，运价第一层分组依据 | `英国空卡铁海` |
| `来源行号` | 源表行号，用于溯源回原表 | `9` |
| `供应商代码` | 供应商代号，多供应商命名空间 | `皓鹏` |
| `渠道名称` | 渠道完整名，由目的地+清关+干线+派送拼装 | `英国不包税_空运5日提普货_DPD派` |
| `运输方式` | 干线/末端，形如 `干线/末端`，前端拆成 head/tail 两段筛选 | `空运/快递派` |
| `交货地` | 可收货城市（**供应商口径**，三家当前恒为 `深圳市`） | `深圳市` |
| `交货仓库` | 交货仓 / 收货区域（**供应商自己怎么写就怎么存**，跨家不可比） | `HP深圳仓` / `华南区域` / `龙岗总仓/福永仓/广州仓/义乌仓` |
| `可收货城市` | **这条价能用在哪些城市收货**（有序城市数组，规范序）；**页端筛选维度**（9/19 起），选某城=包含匹配。值来自解析端受控词表 `CITIES`（15 城）+ `CITY_EXCEPTIONS`（当前空），不是从页端数据反推的 | `["深圳","东莞","广州","义乌","厦门","青岛","泉州"]` |
| `FBA仓库` | 目的地仓库段 | `全部亚马逊仓库` |
| `时效` | 交货/提取时效说明，可含延误赔偿条款，支持多行 | `交货后第二天起6天左右提取/签收` |
| `船期` | 航班/船期说明（**只有 `英国空卡铁海` 带该键**，其余表不带 —— 条数不在文档登记） | `国内/香港优质航班` |
| `体积重量比` | 体积重量换算比，如 `167` 表示 1:167；**只随 KG 记录出现**（CBM 不带该键；条数不在文档登记） | `167` |
| `货柜容量` | 整柜容量（CBM）；**值恒为数字 `68`**（正源 = 解析端 `sheet_configs.CONTAINER_CBM`），前端不使用该字段；**非全量持有**（缺值集中在两张表，见上文「字段口径」；条数不在文档登记） | `68` |
| `开始时间` | 该报价生效日期（**按供应商/表取值**，非全局常量） | `2026-08-13` |
| `货币` | 记录级币种（9/11 新增，历史已回填）；缺键时前端按 `RMB` 兜底 | `RMB` / `USD` |
| `货物类型` | 货型 | `普货` / `带电/敏感` |
| `国家` | 目的地国家（**7 种**） | `英国` |
| `城市` | 邮编区间对应的城市名（仅源表显式给出城市时才有值；**当前只有 `澳大利亚空海` 带**，条数不在文档登记） | `悉尼` |
| `开始邮编` | 目的地邮编区间**下界**；**字符串**，按国家位宽左侧补零；不按邮编分档时为空 | `"1000"` |
| `结束邮编` | 目的地邮编区间**上界**，同上；与 `开始邮编` 构成闭区间 | `"2999"` |
| `是否包税` | 包税标记 | `是` / `否` |
| `单位` | 计费口径（数值本身不带动词） | `KG` / `CBM` / `件` |
| `区间` | 计费区间段编号 + 类别，与来源表名共同构成分组 | `区间1-空运KG` |
| `价格` | 价格档位到单价的映射 | `{"21KG+":40.5,"45KG+":38.5,"100KG+":36.5,"1000KG+":36}` |

目的地显示逻辑：`FBA仓库 → 城市 → 邮编段（开始邮编 - 结束邮编） → "—"` 依次兜底。

给下游计费提示：`单价 × 重量（按 KG）` 或 `单价 × CBM（按体积）`，`单位` 决定乘数，不要把 KG 与 CBM 两套混用。

## 页面结构

- **页头**：标题 + 副标题「数据源 · 已拆解 N 个来源表」+ 四个统计数字。副标题里的来源表数由 JS 从数据实时算出，不会走样
- **发布时间**：**按来源表分别记录**，显示在**表格视图的分组标题**（`N 条 · 单位 X · 发布 YYYY-MM-DD`）与**卡片视图的 meta 区**（`发布`）。日期存在 JS 常量 `PUBLISHED`（**复合键 `供应商代码│来源表名` → 日期**）里，**与 `__FBA_DATA__` 分离**——不往记录里加字段，原始数据一字不动；新增或重新发布某张表时，只改 `PUBLISHED` 里对应那一行。**9/11 起因多供应商改为复合键**（此前是裸表名）：皓鹏与扬程都有名为「美国空运」的 sheet，裸名会让两张表互相覆盖、下拉里还会出现同名选项。**键数 = 已并入的来源表数**（页上多少张表就该有多少个键），终检的「`PUBLISHED` 覆盖率」项会逐表核对，**不在文档里登记条数**（每并一张表都会变）。
  - **口径（已定）**：`发布` = **该表首次上线到查询页的日期**。既不是报价表的有效日期（源表 6 张 sheet 都写 `2026年8月31号`，全表同一天、无法按表区分），也不是记录最近变更日（会被内部字段修正污染）。取值依据 = 查询页仓库的提交历史中「该表数据首次出现」的那次提交。**下列分布是 2026-09-16 的实测快照（当次 29 项），仅供理解口径，不是当前值**：`2026-09-01` × 4（英国空卡铁海 / 澳大利亚空海 / 美中休斯顿海卡 / 美东纽约OA非OA海卡）；`2026-09-10` × 2（美中芝加哥海卡 / 美东萨凡纳海卡）；`2026-09-11` × 23（皓鹏 6 张 + 蓝图梦 13 张 + 巴西海运 / 墨西哥美转墨直航 / 美国空运小货特快 / 美西美东商私卡）。蓝图梦 13 张虽在 9/11 深夜并入，仍归 `2026-09-11` 当天。
- **卡片视图 / 表格视图** 双模式，卡片适合浏览单条详情，表格适合同一来源下的档位对读
  - **表格视图的信息列**：`来源 / 渠道名称 / 运输方式 / **可收货城市** / **交货仓库** / 国家 / 货型 / 包税 / **货币** / 目的地 / 城市 / 开始邮编 / 结束邮编 / 时效`，其后是各价格档位列。**列名、列数、每项宽度、合计宽度都以常量 `TBL_INFO_COLS` 为唯一正源**（9/16 性能改造时由 `renderTable()` 内的 `infoCols` **提升为模块级常量**，供懒渲染复用；文档旧称 `infoCols` 已失效）—— 要当前值跑 `python3 ../fba-rate-parser/tools/current_numbers.py`，**本文件不登记这些会变的数字**。**9/19 的列变化**：引入「可收货城市」时把「交货地」列**换掉**了（宽 66 → 190px），随后又**补回「交货仓库」列**（124px）—— 「交货地」零区分度（全部记录都是「深圳市」）且与「可收货城市」名字只差两个字（用户因此说「出现了 3 种不同的名称」），而**「可收货城市」与「交货仓库」必须同时给**：前者答"我能不能用这个价"（客观、跨家可比），后者答"货送到哪个仓 / 供应商自己怎么划的"（皓鹏 `HP深圳仓`、蓝图梦 `龙岗总仓/…` 是真实收货仓，客户据此发货），两个都有用、不能互相替代。**卡片视图与模板 Excel** 也都保留「交货地」（源表协议原字段，不改名）。表体信息 `<td>` 数必须与 `TBL_INFO_COLS` 列数相等（改列时两者要一起改）—— 终检闸门 ⑧-D 断言这一点；**承诺过的展示字段不得缺失**由 ⑧-E 断言。
  - **命名唯一（9/19，闸门 ⑧ 守住）**：这个字段的名字在**筛选栏 `<label>`、`TBL_INFO_COLS` 列名、卡片 `<span class="k">`** 三处出现，必须**逐字相同**（当前都是 `可收货城市`）；数据字段名与模板列名（`*可收货城市`）也是同一个名字。中途用过的旧名 `交货城市` 已被闸门 ⑧-A 断言**零残留**。
  - **表格容器的滚动与吸顶（9/11 修的背景 bug）**：`.tbl-scroll` **在所有视口都是滚动容器**（`overflow:auto` + `max-height:70vh`），表头 `position:sticky; top:0` 在**容器内**吸顶。原因：表格总宽 = 信息列合计 + 档位数×60 会超过 `.wrap` 的内容宽（上限 1280px），容器若不可滚，表格就会溢出容器，**容器的白底/边框/圆角只铺到容器宽度，右侧档位列透出页面底色**——这正是「字段变长后背景出问题」的根因。
    - **宽度预算（关系式，不是数字）**：`min-width = 信息列合计 + 档位数×60`，需 `+2（边框）≤ 1280` 才不用横滑。**三项都由 `tools/current_numbers.py` 给出**（它会打印列宽列表、合计宽度、档位分布与最宽的分组，并算好 1 档/2 档的 min-width）。**当前结论：常规表默认就要横滑** —— 信息列合计已接近内容宽上限，1 档也放不下（历史口径 1068/1124 时 1–2 档还放得下，那批数字已随列变化失效，故不再登记）。
    - **最宽的分组不是常规表**：件计费专线等少数分组的档位数远高于常规表，`min-width` 相应很大（`current_numbers.py` 会直接告诉你当前最宽的是哪一组、多少档、多少 px）。**别用「常规表最宽 6 档」推断全表** —— 这句话曾让文档低估了整整一档量级。
    - **加列/加档位前先算这笔账**：`信息列合计 + 档位数×60 + 2（边框）≤ 1280`；超了就横滑（容器已兜住，不会再破底），但**不要**为了塞进来把列压到读不清。
    - 注：`--fb-h`（筛选栏高度，JS 在 `documentElement` 上设置）原本用于让表头吸在筛选栏下方，容器成为滚动容器后该用法失效；变量仍在设置、无副作用。
  - **卡片视图的 meta 行**：`来源 / 发布 / 时效 / 目的地 / 交货地 / 交货仓库 / [可收货城市] / [城市] / [开始邮编] / [结束邮编] / [重比]`——方括号内为**有值才显示**（与既有「重比」同处理，避免给大量空记录各挂 3 行空字段）。卡片头部的标签行含 `国家 / 货型 / 包税 / 单位 / **货币**`（货币标签 9/11 新增）；价格区标题为 `PRICE TIERS · <币种符号> 每 <单位>`（`curSym()` 取符号，RMB→`¥`、USD→`$`）。**9/16 性能改造**：卡片视图改为**渐进渲染**（首屏 60 条立即出、其余按帧追加 120 条），故 DOM 不会一次性建满。
- **与模板 Excel 的字段对照**：页面已把 Excel 的 `交货地`、`城市`、`开始邮编`、`结束邮编` 四列**显式呈现**（9/11 补齐；此前这 4 个字段数据里都有，但表格视图没输出、卡片视图又把 `交货地` 藏在 `交货仓库||交货地` 的兜底里、`城市`/邮编只作为 `目的地` 的兜底出现）。**注意口径差异**：Excel 的 `目的地` 是独立一列 `FBA仓库`，页面的 `目的地` 是 `FBA仓库 → 城市 → 邮编段` 的**兜底合并值**，所以有 24 条澳大利亚记录（商业地址区）页面的「目的地」显示城市名而 Excel 的 `FBA仓库` 列为空——这不是缺数据，是兜底显示。

  - **「交货仓库」列的是「最小收货单位」、匹配是「包含」（9/19 当天第二次修，`whAtoms()`）**：用户指出「很多同个区域但重复拆成，福建、华北、华东、华南。比如查华东，包含华东则命中」。扬程的下拉原先有 **8 个选项**，而它们只是同 4 个区域的排列组合（`华东区域`2232 / `华南区域`1578 / `华北区域`639 / `福建区域`852 / `华东/华南区域`84 / `华北/福建区域`810 / `华北/华南/福建区域`857 / `华南/华北/福建区域`196）——本质只有 **4 个区域**。

    - **`区域` 二字怎么处理**：`华北/华南/福建区域` 里的 `区域` 是**整个枚举的后缀**（"华北、华南、福建 **三个区域**"），不是「福建区域」这个专名 → 拆分时统一剥掉，得到 `华东/华南/华北/福建` 四个干净单位（皓鹏 `HP深圳仓`、蓝图梦的 4 个仓名不含该尾缀，拆出来即具体收货仓，同一套规则）。占位项因此改为中性的「全部」（选项里既有区域也有仓名）。
    - **顺带根治了本项目最初那个问题**：`华北/华南/福建区域`(857) 与 `华南/华北/福建区域`(196) 是同一组区域的两种书写，拆成单位后**自然归一** —— 最早那次"下拉选项重复"的根就在于按原文串比较。

  - **布局（9/11 修，9/16 复核，9/19 更新）**：第 1 行 = **10 个下拉**（供应商文件 / **交货仓库（默认隐藏，选了文件才显示 → 常态 9 个）** / 来源表 / 国家 / 头程 / 尾程 / 货物类型 / 是否包税 / **货币** / **可收货城市**；`.frow` 宽屏下 `repeat(auto-fit,minmax(150px,1fr))` 自动均分铺满，故第 10 项出现时会自动换行、不会挤坏）—— **9/19 由 8 个变 9 个、再加级联的第 10 个**；第 2 行 = **「邮编查询」+「关键词搜索」并排**，二者同处一个满宽容器 `.fitem.search`，内部用 `.pair` 两列网格（`minmax(150px,260px) 1fr`）——**不要把「邮编查询」放回 `.frow` 直接子级**，否则它会被挤到单独一行、右侧留白且把筛选栏顶高一行。手机端（≤640px）`.pair` 变单列堆叠。
  - **邮编查询（9/11 新增，同日定稿为「口径 B」）**：输入客户邮编 → 列出该邮编的候选报价。判定两层：**① 位数门**——位数须与记录 `国家` 的位宽一致（5 位=美国、4 位=澳大利亚；位宽正源 = 解析端 `sheet_configs.ZIP_WIDTH`），不符则不命中（否则 4 位澳洲邮编 `2000` 会命中美国 `00000-39999`，纯区间判定下实测误命中 **12 条**）；**② 命中式**——有邮编区间则按解析端协议 **§5.9.3** 的闭区间 `int(开始邮编) ≤ int(客户邮编) ≤ int(结束邮编)` 判定，**无区间则视为「全国统一价、覆盖全境」，一并列出**。输入框下方实时提示（如 `按「美国」5 位匹配（含全国统一价）· 区间命中 16 条`），非 4/5 位标红 `需 4 位或 5 位数字`；输入只保留数字、最多 5 位。已纳入 `activeCount` 与「重置筛选」。
  - **为什么是「口径 B（宽松）」**：查价场景下客户给一个邮编，要看到的是**这个邮编能走的所有报价**；`不按邮编分档` 的表本身就覆盖全境，把它们过滤掉结果会残缺。改前口径（位数门 + 必须落在区间内）实测只剩十几条，**等于输入邮编后几乎什么都看不到**。
  - **两个函数的职责**：`zipHit` = 页面过滤口径（口径 B）；`zipRangeHit` = 纯闭区间判定，**只用于**输入框下方「区间命中 N 条」的计数提示，不参与结果过滤。
  - **代价与配套（下组数字是 2026-09-16 用页面自身函数 `zipHit` / `zipRangeHit` 的实测快照，随数据增长，不是当前值）**：结果面显著变宽 —— 美国邮编（如 `10001` / `90001` / `00001`）口径 B 命中 2936 条、纯区间 16 条；澳洲 `2000` 口径 B 28 条、纯区间 20 条。这是**预期行为**（含"全国统一价"的美国记录中的绝大部分），命中后应配合其他筛选项（来源表 / 尾程 / 货型 / 货币）收窄。**要当前的命中数**：在浏览器里用页面自身函数现算（`DATA.filter(...)` 的 `.length`）—— 这也正是终检 ⑦-E 的做法（它对城市筛选 17 个探针逐个直接跑页面 `filter()` 并与数据侧独立算出的值比对）。
- **长文本处理**：被两行截断的「渠道名称 / 目的地 / 时效」可点击弹气泡看全文；页面滚动或缩放时气泡自动收起
- 价格区间列在表格中均分剩余宽度，并设有最小可视宽度，避免手机端挤压重叠

## 渲染性能（9/16 优化，改动前必读）

**结论先行：`filter()` 不是瓶颈**。**2026-09-16 实测（当次数据 3506 条）** `filter()` 仅 **0.6 ms**；改动前的 193 ms 全部来自**「每次输入都全量重建 DOM + 强制布局」**。故优化只动渲染层、**未碰筛选逻辑**。下表与本节其余数字都是**那一次的历史记录**，不是当前红线。

| 操作 | 改前 | 改后 |
|---|---|---|
| 输入关键词 → 出结果 | 240 ms 阻塞 | **41.9 ms**（32.7 渲染 + 9.2 布局） |
| 打字过程中每字符 | 240 ms 堆积 | **0.1 ms**（防抖吞掉） |
| 初始 DOM 节点 | 104,153 | **360**（-99.7%） |
| 全展开后 tbody / 行数 | 45 / 3551 | 45 / 3551（**一致，无回归**） |

**五条措施**（按贡献排序）：

1. **分组懒渲染**（主要功臣）：原实现**收起的分组照样生成完整 `<tbody>`**，只套 `.closed` 用 CSS 隐藏——节点一个不少。现改为收起即真空、点击时才现场生成（`groupCache` + `buildTableHtml(gk)`）。
2. **自动展开设上限**：原判据 `activeCount() === 0` 意味着**只要输入过搜索词就把全部分组展开**（这是 193 ms 的来源）。现为 `AUTO_EXPAND_MAX_GROUPS = 3` 且 `AUTO_EXPAND_MAX_ROWS = 400` **同时满足**才自动展开，否则保持目录态。交互语义未变（默认收起、点标题展开）。
3. **输入防抖 180 ms**：**邮编框的数字回显刻意不防抖**（那是即时反馈，防抖会让手感变黏），只延迟渲染。
4. **`bindOverflow` 三重优化**：原每次重扫 14,024 个 `td` 读 `scrollWidth`（强制同步布局，31 ms），而**真实溢出是 0 个**。现推迟到 `requestIdleCallback` + 已判定的跳过 + 不可见的不判定。**第三条最要紧**：收起分组内 `offsetParent` 为空、`scrollWidth` 恒为 0，若照此缓存「未溢出」，展开后就再也不判了。
5. **卡片视图渐进渲染**：首屏 60 条立即出，其余按帧追加 120 条。

**回归红线：`td.ov` / `data-full` / 展开后的 tbody 与行数 —— 测法与实测记录见 [`渲染基线.md`](渲染基线.md)。**

**本文件不再在这些数字上钉一个「必须等于 X」**：它们是**真实布局测量**结果，依赖当次的数据规模
（记录数、分组数、列宽），而数据几乎每周都在变 —— 钉死的结果是"每次并表都要重算、还没人记得"。
`渲染基线.md` 里写清了**怎么测**（HTTP 打开 + 全展开 + 一段只读 JS）与**历次实测记录表**，
**当前状态是「未实测」**（9/19 把「交货地」列换成「可收货城市」列之后没测过，写明了，不装作有）。

> **改过列数 / 列宽 / 单元格内容 / 字体后，必须按那份文档重测一次并追加一行。**
> **不要用「预期不增」代替实测** —— 9/19 那次就是只在文档里写了预期、没测，那种断言等于没有断言。
> 另：宽度账同样是关系式（见上文「宽度预算」），当前值由 `tools/current_numbers.py` 现算。
> **命名唯一**由终检闸门 ⑧ 守住（旧名零残留 / 三处展示名逐字相同 / 表格无近义城市列名 / 列数与表体 `<td>` 数一致），
> 负向用例在 `fba-rate-parser/tools/test_page_gates.py`（对 `verify_page_after_merge.py --page` 注入缺陷）。

## 更新流程

1. 用 fba-rate-parser 拆解新表 → 确认 → 导出页面数据
2. 重新生成 `index.html`（**2026-09-19 起页面只有这一个文件**：它既是交付物、也是 GitHub Pages 根路径入口）
3. **在页面 JS 的 `PUBLISHED` 常量里，写入本次发布那张表的日期**——键为**复合键 `供应商代码│来源表名`**（分隔符 `│` = `\u2502`，与页面分组键同；**9/11 起不再用裸表名**，否则跨供应商同名表会互相覆盖）。**9/16 起写键不再需要手工 trim**：源表名已在解析端规范（`美东纽约OA非OA海卡` 的尾随空格已去除，见查询页 `d4685c8`）。口径为**该表本次上线日**（即当天），人工维护、不会自动更新
4. **落盘前跑 `node --check`**（并入器已内建「写入即语法自检」—— 曾因 `PUBLISHED` 漏一个逗号导致**页面白屏**，而「记录数正确」这一项**察觉不到**）
5. `git add . && git commit -m "update: <说明>" && git push origin main`
6. GitHub Actions 自动部署，约 1-2 分钟生效；**部署后拉取线上页面与本地比对 sha256**（9/16 前 4 次数据变更均逐字节一致）

推送网络方案见 `DECISION_LOG.md`。

```bash
python3 tools/chat_query.py 城市=义乌 包税=是 重量档=21KG+
```

**参数**（除 `单位` 精确相等，其余为**包含**匹配、大小写不敏感）：`国家 / 供应商 / 来源表 / 渠道 / 运输 / 货型 / 包税 / 货币`（对同名字段；`供应商` 实际比对 `供应商代码`）、`城市`（对 `可收货城市` 数组逐项子串，与页端口径一致）、`单位`（`KG` / `CBM` / `件`）、`重量档`（只保留 `价格` 里含该档位名的记录）、`limit`（**组数**上限，默认 10）。**参数拼错直接报错**，不静默忽略。

**归并口径（本脚本的关键，改前必读）**：按 `供应商代码 / 来源表名 / 渠道名称 × 单位 × 区间` 归并成一行，行末 `〔N 条〕` 给出被归并的原始记录数。两条纪律均来自 2026-09-25 的实测：

- **「单位 × 区间」必须进归并键** —— 同一渠道名可能同时有 KG 与 CBM 两条（实测 **50 组**跨区间、含单位分叉）。**只按渠道名归并会静默少给一半的价**，原实现即如此（已修）。
- **同组逐档位取 `最小~最大`** —— 同组的 `价格` 会因**邮编段 / 时效**分叉（实测 **337/389 组**不一致），只取第一条同样少给；数值相同时打印单值。
- 另有 `assert` 断言**归并前后条数相等** —— 防的就是"静默少给"这一类。

**价格格式**：与页端 `fmtPrice()` 同口径（整数带千分位、非整数留 2 位去尾零）。页端 `title` 里的**精确值**（`fmtFull()`，如 `8.51096022241232`）本脚本不打印。**`__FBA_MARKUP__`（利润层）不参与** —— 只回成本价，要含利润的展示值看页面。
