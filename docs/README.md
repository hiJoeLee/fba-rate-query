# FBA 运价查询台

供应商 FBA 运价表拆解结果的查询页面（纯静态单文件）。

- **线上网址**：https://hijoelee.github.io/fba-rate-query/
- **数据源**：fba-rate-parser 拆解输出（**3 家供应商 / 46 张来源表 / 9599 条记录**，详见下）
- **技术**：单文件 HTML + 内嵌 JSON，零依赖、免后端、免登录、手机自适应
- **部署**：GitHub Pages（推送 `main` 分支自动部署，免费无次数限制）

> **末端的两种缺省不是同一回事**：`海运/卡派` 等的末端是源表明写的派送方式；而 `空运`/`海运`/`卡航`/`铁路` 四种**没有末端**，源表该行只标了干线（欧洲表的「直送」行则在 `运输方式` 第二位写 `直送`）。前端 `splitMode` 对无末端的写法**原样返回空串**——**9/11 修**：旧式 `(b||'').replace(/派$/,'')+'派'` 会把无末端补成 `派`、把 `直送` 补成 `直送派`（都不是真实术语），已改为恒等解析（对存量 2996 条是严格无操作，因为它们的末端本就都以「派」结尾；此后新增的 168 条裸头程因此得到**空末端**而非假 `派`）。

## 字段字典

每一条记录代表「某个来源表里、某一计费区间段下、某个渠道的一个订单行」，对应的单价档位放在 `价格` 对象里。

| 字段 | 含义 | 取值示例 |
|---|---|---|
| `文件` | 数据批次 / 来源 Excel 文件名标识 | `皓鹏国际同行vip8月31日` |
| `来源表名` | 源表 Sheet 名，运价第一层分组依据 | `英国空卡铁海` |
| `来源行号` | 源表行号，用于溯源回原表 | `9` |
| `供应商代码` | 供应商代号，多供应商命名空间 | `皓鹏` |
| `渠道名称` | 渠道完整名，由目的地+清关+干线+派送拼装 | `英国不包税_空运5日提普货_DPD派` |
| `运输方式` | 干线/末端，形如 `干线/末端`，前端拆成 head/tail 两段筛选 | `空运/快递派` |
| `交货地` | 交货城市（**供应商口径**，三家当前恒为 `深圳市`） | `深圳市` |
| `交货仓库` | 交货仓 / 收货区域（**供应商自己怎么写就怎么存**，跨家不可比） | `HP深圳仓` / `华南区域` / `龙岗总仓/福永仓/广州仓/义乌仓` |
| `交货城市` | **这条价能用在哪些城市收货**（有序城市数组，规范序）；**页端筛选维度**（9/19 起），选某城=包含匹配。值来自解析端受控词表 `CITIES`（15 城）+ `CITY_EXCEPTIONS`（当前空），不是从页端数据反推的 | `["深圳","东莞","广州","义乌","厦门","青岛","泉州"]` |
| `FBA仓库` | 目的地仓库段 | `全部亚马逊仓库` |
| `时效` | 交货/提取时效说明，可含延误赔偿条款，支持多行 | `交货后第二天起6天左右提取/签收` |
| `船期` | 航班/船期说明（**9/16 实测仅 `英国空卡铁海` 125 条有值**，其余 28 张表不带该键） | `国内/香港优质航班` |
| `体积重量比` | 体积重量换算比，如 `167` 表示 1:167；**9/16 实测 2098 条持有**（KG 填、CBM 不带） | `167` |
| `货柜容量` | 整柜容量（CBM）；**值恒为数字 `68`**（正源 = 解析端 `sheet_configs.CONTAINER_CBM`），前端不使用该字段；**非全量持有**，9/16 实测 **3412 / 3506** | `68` |
| `开始时间` | 该报价生效日期（**按供应商/表取值**，非全局常量） | `2026-08-13` |
| `货币` | 记录级币种（9/11 新增，历史已回填）；缺键时前端按 `RMB` 兜底 | `RMB` / `USD` |
| `货物类型` | 货型 | `普货` / `带电/敏感` |
| `国家` | 目的地国家（**7 种**） | `英国` |
| `城市` | 邮编区间对应的城市名（仅源表显式给出城市时才有值；**9/16 实测仅 `澳大利亚空海` 24 条**） | `悉尼` |
| `开始邮编` | 目的地邮编区间**下界**；**字符串**，按国家位宽左侧补零；不按邮编分档时为空 | `"1000"` |
| `结束邮编` | 目的地邮编区间**上界**，同上；与 `开始邮编` 构成闭区间 | `"2999"` |
| `是否包税` | 包税标记 | `是` / `否` |
| `单位` | 计费口径（数值本身不带动词） | `KG` / `CBM` / `件` |
| `区间` | 计费区间段编号 + 类别，与来源表名共同构成分组 | `区间1-空运KG` |
| `价格` | 价格档位到单价的映射 | `{"21KG+":40.5,"45KG+":38.5,"100KG+":36.5,"1000KG+":36}` |

目的地显示逻辑：`FBA仓库 → 城市 → 邮编段（开始邮编 - 结束邮编） → "—"` 依次兜底。

给下游计费提示：`单价 × 重量（按 KG）` 或 `单价 × CBM（按体积）`，`单位` 决定乘数，不要把 KG 与 CBM 两套混用。

## 页面结构

- **页头**：标题 + 副标题「数据源 · 已拆解 N 个来源表」+ 四个统计数字。副标题里的来源表数由 JS 从数据实时算出，不会走样
- **发布时间**：**按来源表分别记录**，显示在**表格视图的分组标题**（`N 条 · 单位 X · 发布 YYYY-MM-DD`）与**卡片视图的 meta 区**（`发布`）。日期存在 JS 常量 `PUBLISHED`（**复合键 `供应商代码│来源表名` → 日期**）里，**与 `__FBA_DATA__` 分离**——不往记录里加字段，原始数据一字不动；新增或重新发布某张表时，只改 `PUBLISHED` 里对应那一行。**9/11 起因多供应商改为复合键**（此前是裸表名）：皓鹏与扬程都有名为「美国空运」的 sheet，裸名会让两张表互相覆盖、下拉里还会出现同名选项。当前 **29 项**。
  - **口径（已定）**：`发布` = **该表首次上线到查询页的日期**。既不是报价表的有效日期（源表 6 张 sheet 都写 `2026年8月31号`，全表同一天、无法按表区分），也不是记录最近变更日（会被内部字段修正污染）。取值依据 = 查询页仓库 `fba-rate-query.html` 的提交历史中「该表数据首次出现」的那次提交。**9/16 实测当前分布**：`2026-09-01` × 4（英国空卡铁海 / 澳大利亚空海 / 美中休斯顿海卡 / 美东纽约OA非OA海卡）；`2026-09-10` × 2（美中芝加哥海卡 / 美东萨凡纳海卡）；`2026-09-11` × **23**（皓鹏 6 张 + **蓝图梦 13 张** + 巴西海运 / 墨西哥美转墨直航 / 美国空运小货特快 / 美西美东商私卡）。蓝图梦 13 张虽在 9/11 深夜并入，仍归 `2026-09-11` 当天。
- **卡片视图 / 表格视图** 双模式，卡片适合浏览单条详情，表格适合同一来源下的档位对读
  - **表格视图的信息列（14 列）**：`来源 / 渠道名称 / 运输方式 / 交货地 / **可收货城市** / 国家 / 货型 / 包税 / **货币** / 目的地 / 城市 / 开始邮编 / 结束邮编 / 时效`，其后是各价格档位列。**9/11 由 8 列扩到 12，9/11 再加「货币」列 → 13 列；9/19 加「可收货城市」列（插在「交货地」之后、宽 190px）→ 14 列**。**列宽正源 = 常量 `TBL_INFO_COLS`**（9/16 性能改造时由 `renderTable()` 内的 `infoCols` **提升为模块级常量**，供懒渲染复用；文档旧称 `infoCols` 已失效），当前合计 **1314px**；表体字面 `<td>` 数必须与之相等（改列时两者要一起改，否则列会错位）。
  - **表格容器的滚动与吸顶（9/11 修的背景 bug）**：`.tbl-scroll` **在所有视口都是滚动容器**（`overflow:auto` + `max-height:70vh`），表头 `position:sticky; top:0` 在**容器内**吸顶。原因：表格总宽 = 信息列合计 + 档位数×60 会超过 `.wrap` 的内容宽（上限 1280px），容器若不可滚，表格就会溢出容器，**容器的白底/边框/圆角只铺到容器宽度，右侧档位列透出页面底色**——这正是「字段变长后背景出问题」的根因。
    - **宽度预算（9/19 按 `TBL_INFO_COLS` 重算，内容宽上限 1280px = `.wrap` 1320 − 40 内边距）**：`min-width = 1314 + 档位数×60`。**1314 + 2（边框）= 1316 > 1280 → 1 档起就需横滑**（旧口径 1124 时 1 档 1184 / 2 档 1244 还放得下，「9/16 记 1–2 档放得下」已不成立）。加「可收货城市」列的**代价就是这里**：容器已兜住横滑，不会再破底，但要清楚**常规表默认就要横滑了**。
    - **最宽的分组不是 6 档而是 22 档**：`美国空运小货特快` 的 2 条「小货特快专线」（单位=件）**各带 22 个档位**（`0.5KG` – `11KG` 每 0.5 一档），min-width 达 **2634px**（9/19 重算：1314 + 22×60）。**9/16 实测分组档位数分布**：1 档 × 31 组、2 档 × 14、3 档 × 47、4 档 × 80、5 档 × 16、6 档 × 4、**22 档 × 2**（共 194 组）。此前文档写「最宽是美国空运 6 档」**有误** —— 6 档只是「常规表里最宽」，另有 22 档的件计费专线。
      - **加列/加档位时先算这笔账**：`1314（当前信息列合计）+ 档位数×60 + 2（边框）≤ 1280` 才不用横滑；超了就横滑（容器已兜住，不会再破底），但**不要**为了塞进来把列压到读不清。
    - 注：`--fb-h`（筛选栏高度，JS 在 `documentElement` 上设置）原本用于让表头吸在筛选栏下方，容器成为滚动容器后该用法失效；变量仍在设置、无副作用。
  - **卡片视图的 meta 行**：`来源 / 发布 / 时效 / 目的地 / 交货地 / 交货仓库 / [可收货城市] / [城市] / [开始邮编] / [结束邮编] / [重比]`——方括号内为**有值才显示**（与既有「重比」同处理，避免给大量空记录各挂 3 行空字段）。卡片头部的标签行含 `国家 / 货型 / 包税 / 单位 / **货币**`（货币标签 9/11 新增）；价格区标题为 `PRICE TIERS · <币种符号> 每 <单位>`（`curSym()` 取符号，RMB→`¥`、USD→`$`）。**9/16 性能改造**：卡片视图改为**渐进渲染**（首屏 60 条立即出、其余按帧追加 120 条），故 DOM 不会一次性建满。
- **与模板 Excel 的字段对照**：页面已把 Excel 的 `交货地`、`城市`、`开始邮编`、`结束邮编` 四列**显式呈现**（9/11 补齐；此前这 4 个字段数据里都有，但表格视图没输出、卡片视图又把 `交货地` 藏在 `交货仓库||交货地` 的兜底里、`城市`/邮编只作为 `目的地` 的兜底出现）。**注意口径差异**：Excel 的 `目的地` 是独立一列 `FBA仓库`，页面的 `目的地` 是 `FBA仓库 → 城市 → 邮编段` 的**兜底合并值**，所以有 24 条澳大利亚记录（商业地址区）页面的「目的地」显示城市名而 Excel 的 `FBA仓库` 列为空——这不是缺数据，是兜底显示。
- **筛选栏**：文件、来源表、国家、运输方式（干线/末端）、货型、包税、**货币**、**交货城市**、**邮编查询**、关键词，支持折叠
  - **筛选项共 11 个**（`state` 键：`file / src / country / head / tail / goods / tax / cur / city / q / zip`），`activeCount()` 据此统计「N 项生效」。**9/11 新增「货币」**（`#f-cur`，选项由数据实时去重填充：`RMB / USD`）。**9/19 把「交货仓库」换成「交货城市」**（`#f-city`）：仓库取值是**供应商自定义词汇**（扬程 `华东区域` / 皓鹏 `HP深圳仓` / 蓝图梦 `龙岗总仓/…`，10 个取值混三种语义，跨家不可比），而城市是**跨家可比的客观标准**。`交货仓库` **字段仍保留**（卡片与搜索里可见），只是不再作筛选维度。
  - **「交货城市」的语义（9/19，含匹配、非精确匹配）**：选某城 → 命中所有 `交货城市` **包含**该城的记录（一条价按供应商收货区域给价、可覆盖多城，故同一记录会被多城筛到，这是对的）。选项 = **受控 15 城 + 「其他」**，**不是**从数据去重（若从数据去重，`台州 / 武汉 / 福州 / 郑州` 这 4 个名单内、三家无仓的城市根本不会出现在下拉里，用户会以为该城市压根不覆盖）。选这 4 城 → **0 条**，这是"真缺口"的如实反映。
  - **「其他」= 至少含一个名单外城市**（`__other__` 哨兵值），**与名单内选项可重叠**：跨界记录（同一价同时覆盖名单内与名单外城市）既能在名单内城市筛到、也能在「其他」筛到，**不会漏价**。若定义成"只当全在城市外才算"，则「其他」几乎永远为空、等于白设。**当前命中 0 条**（例外登记为空、三家城市全在 15 城内），机制先立。
  - **城市词表正源**：解析端 `sheet_configs.CITIES` / `CITY_EXCEPTIONS`，由工具写入页面的 `CITY_LIST` 常量；**不在页端另立一份**。
  - **布局（9/11 修，9/16 复核，9/19 更新）**：第 1 行 = **9 个下拉**（供应商文件 / 来源表 / 国家 / 头程 / 尾程 / 货物类型 / 是否包税 / **货币** / **交货城市**；`.frow` 宽屏下 `repeat(auto-fit,minmax(150px,1fr))` 自动均分铺满）—— **9/19 由 8 个变 9 个**；第 2 行 = **「邮编查询」+「关键词搜索」并排**，二者同处一个满宽容器 `.fitem.search`，内部用 `.pair` 两列网格（`minmax(150px,260px) 1fr`）——**不要把「邮编查询」放回 `.frow` 直接子级**，否则它会被挤到单独一行、右侧留白且把筛选栏顶高一行。手机端（≤640px）`.pair` 变单列堆叠。
  - **邮编查询（9/11 新增，同日定稿为「口径 B」）**：输入客户邮编 → 列出该邮编的候选报价。判定两层：**① 位数门**——位数须与记录 `国家` 的位宽一致（5 位=美国、4 位=澳大利亚；位宽正源 = 解析端 `sheet_configs.ZIP_WIDTH`），不符则不命中（否则 4 位澳洲邮编 `2000` 会命中美国 `00000-39999`，纯区间判定下实测误命中 **12 条**）；**② 命中式**——有邮编区间则按解析端协议 **§5.9.3** 的闭区间 `int(开始邮编) ≤ int(客户邮编) ≤ int(结束邮编)` 判定，**无区间则视为「全国统一价、覆盖全境」，一并列出**。输入框下方实时提示（如 `按「美国」5 位匹配（含全国统一价）· 区间命中 16 条`），非 4/5 位标红 `需 4 位或 5 位数字`；输入只保留数字、最多 5 位。已纳入 `activeCount` 与「重置筛选」。
  - **为什么是「口径 B（宽松）」**：查价场景下客户给一个邮编，要看到的是**这个邮编能走的所有报价**；`不按邮编分档` 的表本身就覆盖全境，把它们过滤掉结果会残缺。改前口径（位数门 + 必须落在区间内）实测只剩十几条，**等于输入邮编后几乎什么都看不到**。
  - **两个函数的职责**：`zipHit` = 页面过滤口径（口径 B）；`zipRangeHit` = 纯闭区间判定，**只用于**输入框下方「区间命中 N 条」的计数提示，不参与结果过滤。
  - **代价与配套（9/16 用页面自身函数 `zipHit` / `zipRangeHit` 实测复算）**：结果面显著变宽 —— 美国邮编（如 `10001` / `90001` / `00001`）口径 B 命中 **2936 条**、纯区间 **16 条**；澳洲 `2000` 口径 B **28 条**、纯区间 **20 条**。这是**预期行为**（含"全国统一价"的 2968 条美国记录中的绝大部分），命中后应配合其他筛选项（来源表 / 尾程 / 货型 / 货币）收窄。
- **长文本处理**：被两行截断的「渠道名称 / 目的地 / 时效」可点击弹气泡看全文；页面滚动或缩放时气泡自动收起
- 价格区间列在表格中均分剩余宽度，并设有最小可视宽度，避免手机端挤压重叠

## 渲染性能（9/16 优化，改动前必读）

**结论先行：`filter()` 不是瓶颈**。3506 条实测 `filter()` 仅 **0.6 ms**；改动前的 193 ms 全部来自**「每次输入都全量重建 DOM + 强制布局」**。故优化只动渲染层、**未碰筛选逻辑**。

| 操作 | 改前 | 改后 |
|---|---|---|
| 输入关键词 → 出结果 | 240 ms 阻塞 | **41.9 ms**（32.7 渲染 + 9.2 布局） |
| 打字过程中每字符 | 240 ms 堆积 | **0.1 ms**（防抖吞掉） |
| 初始 DOM 节点 | 104,153 | **360**（-99.7%） |
| 全展开后 tbody / 行数 | 45 / 3551 | 45 / 3551（**一致，无回归**） |

**五条措施**（按贡献排序）：

1. **分组懒渲染**（主要功臣）：原实现**收起的分组照样生成完整 `<tbody>`**，只套 `.closed` 用 CSS 隐藏——节点一个不少。现改为收起即真空、点击时才现场生成（`groupCache` + `buildTableHtml(gk)`）。
2. **自动展开设上限**：原判据 `activeCount() === 0` 意味着**只要输入过搜索词就把全部分组展开**（这是 193 ms 的来源）。现为 `AUTO_EXPAND_MAX_GROUPS = 3` 且 `AUTO_EXPAND_MAX_ROWS = 400` **同时满足**才自动展开，否则保持目录态。交互语义未变（默认收起、点标题展开）。
3. **输入防抖 180 ms**：**邮编框的数字回显刻意不防抖**（那是即时反馈，防抖会让手感变黏），只延迟渲染。
4. **`bindOverflow` 三重优化**：原每次重扫 14,024 个 `td` 读 `scrollWidth`（强制同步布局，31 ms），而**真实溢出是 0 个**。现推迟到 `requestIdleCallback` + 已判定的跳过 + 不可见的不判定。**第三条最要紧**：收起分组内 `offsetParent` 为空、`scrollWidth` 恒为 0，若照此缓存「未溢出」，展开后就再也不判了。
5. **卡片视图渐进渲染**：首屏 60 条立即出，其余按帧追加 120 条。

**回归红线**：`td.ov`（长文本气泡标记）**必须仍是 858 个** —— 它依赖真实布局测量，是懒渲染最容易改坏的路径。改前改后同条件均为 858；另有「`data-full` 单元格 14,024」「全展开 tbody 45 / 行 3551」「列名与顺序」三项须一并核对。懒渲染首次生成的结果需与直接调用 `buildTableHtml()` 逐字符比对。

> ⚠️ **2026-09-19 加「可收货城市」列后，上面这组数字须重新实测**：
> 表格信息列 **13 → 14 列**（列名与顺序见上文），`TBL_INFO_COLS` 合计 **1124 → 1314px**，
> 且**新增列本身带 `data-full`** —— 若其内容在 190px 宽、两行截断下溢出，`td.ov` 与 `data-full` **两个计数都会变**。
> **预期不增**（最长城市串 `广州/深圳/东莞/义乌/宁波/上海/杭州/中山` 共 23 字符，两行可容纳），
> 但这是**推断、非实测**：本次改造时 headless Chrome 在本机沙箱内起不来，故**没有实测数据**。
> 落地前请在浏览器里按同条件（全展开）数一遍，并把实测值写回本节。
> 另：宽度账已重算 → **常规表默认就要横滑**（1314 + 2 > 1280），这是加该列的已知代价。

## 更新流程

1. 用 fba-rate-parser 拆解新表 → 确认 → 导出页面数据
2. 重新生成 `index.html`（**2026-09-19 起页面只有这一个文件**：它既是交付物、也是 GitHub Pages 根路径入口）
3. **在页面 JS 的 `PUBLISHED` 常量里，写入本次发布那张表的日期**——键为**复合键 `供应商代码│来源表名`**（分隔符 `│` = `\u2502`，与页面分组键同；**9/11 起不再用裸表名**，否则跨供应商同名表会互相覆盖）。**9/16 起写键不再需要手工 trim**：源表名已在解析端规范（`美东纽约OA非OA海卡` 的尾随空格已去除，见查询页 `d4685c8`）。口径为**该表本次上线日**（即当天），人工维护、不会自动更新
4. **落盘前跑 `node --check`**（并入器已内建「写入即语法自检」—— 曾因 `PUBLISHED` 漏一个逗号导致**页面白屏**，而「记录数正确」这一项**察觉不到**）
5. `git add . && git commit -m "update: <说明>" && git push origin main`
6. GitHub Actions 自动部署，约 1-2 分钟生效；**部署后拉取线上页面与本地比对 sha256**（9/16 前 4 次数据变更均逐字节一致）

推送网络方案见 `DECISION_LOG.md`。
