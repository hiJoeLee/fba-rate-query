# FBA 运价查询台

供应商 FBA 运价表拆解结果的查询页面（纯静态单文件）。

- **线上网址**：https://hijoelee.github.io/fba-rate-query/
- **数据源**：fba-rate-parser 拆解输出（皓鹏国际同行 vip 8月31日，**11 张来源表，2996 条记录**）
- **技术**：单文件 HTML + 内嵌 JSON，零依赖、免后端、免登录、手机自适应
- **部署**：GitHub Pages（推送 `main` 分支自动部署，免费无次数限制）

## 数据概览

当前数据集字段：`文件 / 来源表名 / 来源行号 / 供应商代码 / 渠道名称 / 运输方式 / 交货地 / 交货仓库 / FBA仓库 / 时效 / 船期 / 体积重量比 / 开始时间 / 货物类型 / 国家 / 是否包税 / 单位 / 区间 / 价格`；美系海卡表（休斯顿/纽约/芝加哥）另带 `货柜容量`，且**不带** `船期`。

**字段口径（含已清理的历史遗留）**：

- `货柜容量`：现为数字 `68`（对应解析端 `CONTAINER_CBM`）。历史上这里存的是 `"1900-03-08"`——Excel 把 `68` 当日期序列号误存，**已于 9/10 修正 413 条**。前端不使用该字段（数据块之外 0 处引用）。注：另有 94 条记录本就不带此键（持有不一致），未处理。
- `体积重量比`：**KG 记录填 `167`、CBM 记录不带该键**（前端渲染「重比 1:167」）。该口径**已两端统一**——9/10 裁定以页面为准，解析端改为「KG→167 / CBM→空」。`167` 对应源表空运口径「长cm × 宽cm × 高cm / 6000」。
- `时效`/`运输方式`：解析端存原始派送方式（如 `DPD派`）与空时效，页面入页时补全为 `干线/末端`（如 `空运/快递派`）并回填源表的时效说明。**入页不是纯机械转换**，新表并入时需按此补全。
- `开始邮编`/`结束邮编`：**区间对**，**字符串类型**，按国家位宽左侧补零（美国 5 / 澳大利亚 4；正源 = 解析端 `sheet_configs.ZIP_WIDTH`）。二者构成**闭区间**，消费端命中判定为 `int(开始邮编) ≤ int(客户邮编) ≤ int(结束邮编)`。本页当前仅**澳大利亚 24 条**有值（`"1000"`–`"2999"` 等）；其余记录为空串（或本就不带该键），表示**不按邮编分档**，不参与邮编命中，**不要当成 `0`**。
  - **来源已收口到解析端（9/11）**：这 24 条原是本页手工补录的，现已确认**源表 `澳大利亚空海!U9:U14` 本就写着**「城市 + 邮编区间」（`悉尼\n1000-2999` 等），解析端已改为从源表产出。本页这 48 组「渠道 × 行 × 区间 × FBA仓库 × 城市 × 邮编」与解析端**逐条完全一致**，**本页数据未改动**（原先补录的值就是对的）。解析端现为该字段正源，后续新增澳洲表不必再手工补。
  - **9/11 之前这里存的是数字**（`1000`），已统一迁移为字符串（`"1000"`）——两端口径一致。**不能用数字存**：美国 `00000` 会退化成 `0`，前导零丢失；且 JS 里 `'00000' <= 20000` 会退化成字符串比较，结果错误。完整口径（含位宽表、双源形态、美国三段区间、连续列表前提）见解析端协议 §5.9。

## 字段字典

每一条记录代表「某个来源表里、某一计费区间段下、某个渠道的一个订单行」，对应的单价档位放在 `价格` 对象里。

| 字段 | 含义 | 取值示例 |
|---|---|---|
| `文件` | 数据批次 / 来源 Excel 文件名标识 | `皓鹏国际同行vip8月31日` |
| `来源表名` | 源表 Sheet 名，运价第一层分组依据 | `英国空卡铁海` |
| `来源行号` | 源表行号，用于溯源回原表 | `9` |
| `供应商代码` | 供应商代号，多供应商命名空间 | `皓鹏` |
| `渠道名称` | 渠道完整名，由目的地+清关+干线+派送拼装 | `英国不包税_空运5日提普货_DPD派` |
| `运输方式` | 干线/末端，形如 `干线/末端`，前端拆成 head/tail 两段筛选 | `空运/快递派` |
| `交货地` | 交货城市 | `深圳市` |
| `交货仓库` | 交货仓 | `HP深圳仓` |
| `FBA仓库` | 目的地仓库段 | `全部亚马逊仓库` |
| `时效` | 交货/提取时效说明，可含延误赔偿条款，支持多行 | `交货后第二天起6天左右提取/签收` |
| `船期` | 航班/船期说明 | `国内/香港优质航班` |
| `体积重量比` | 体积重量换算比，如 `167` 表示 1:167 | `167` |
| `开始时间` | 该报价生效日期 | `2026-08-13` |
| `货物类型` | 货型 | `普货` / `带电/敏感` |
| `国家` | 目的地国家 | `英国` |
| `城市` | 邮编区间对应的城市名（仅源表显式给出城市时才有值，目前仅澳大利亚） | `悉尼` |
| `开始邮编` | 目的地邮编区间**下界**；**字符串**，按国家位宽左侧补零；不按邮编分档时为空 | `"1000"` |
| `结束邮编` | 目的地邮编区间**上界**，同上；与 `开始邮编` 构成闭区间 | `"2999"` |
| `是否包税` | 包税标记 | `是` / `否` |
| `单位` | 计费口径（数值本身不带动词） | `KG` / `CBM` |
| `区间` | 计费区间段编号 + 类别，与来源表名共同构成分组 | `区间1-空运KG` |
| `价格` | 价格档位到单价的映射 | `{"21KG+":40.5,"45KG+":38.5,"100KG+":36.5,"1000KG+":36}` |

目的地显示逻辑：`FBA仓库 → 城市 → 邮编段（开始邮编 - 结束邮编） → "—"` 依次兜底。

给下游计费提示：`单价 × 重量（按 KG）` 或 `单价 × CBM（按体积）`，`单位` 决定乘数，不要把 KG 与 CBM 两套混用。

## 页面结构

- **页头**：标题 + 副标题「数据源 · 已拆解 N 个来源表」+ 四个统计数字。副标题里的来源表数由 JS 从数据实时算出，不会走样
- **发布时间**：**按来源表分别记录**，显示在**表格视图的分组标题**（`N 条 · 单位 X · 发布 YYYY-MM-DD`）与**卡片视图的 meta 区**（`发布`）。日期存在 JS 常量 `PUBLISHED`（来源表名 → 日期）里，**与 `__FBA_DATA__` 分离**——不往记录里加字段，原始数据一字不动；新增或重新发布某张表时，只改 `PUBLISHED` 里对应那一行
  - **口径（已定）**：`发布` = **该表首次上线到查询页的日期**。既不是报价表的有效日期（源表 6 张 sheet 都写 `2026年8月31号`，全表同一天、无法按表区分），也不是记录最近变更日（会被内部字段修正污染）。取值依据 = 查询页仓库 `fba-rate-query.html` 的提交历史中「该表数据首次出现」的那次提交。当前值：英国空卡铁海 / 澳大利亚空海 / 美中休斯顿海卡 / 美东纽约OA非OA海卡 = `2026-09-01`；美中芝加哥海卡 / 美东萨凡纳海卡 = `2026-09-10`；加拿大空海 / 美西洛杉矶海卡特惠 / 美森以星合德OA非OA海卡 / 美森以星合德OA非OA海派 / 美国空运 = `2026-09-11`
- **卡片视图 / 表格视图** 双模式，卡片适合浏览单条详情，表格适合同一来源下的档位对读
  - **表格视图的信息列（12 列，9/11 由 8 列扩到 12）**：`来源 / 渠道名称 / 运输方式 / 交货地 / 国家 / 货型 / 包税 / 目的地 / 城市 / 开始邮编 / 结束邮编 / 时效`，其后是各价格档位列。**列宽正源** = `renderTable()` 里的 `infoCols`（当前合计 **1068px**）；表体字面 `<td>` 数必须与之相等（改列时两者要一起改，否则列会错位）。
  - **表格容器的滚动与吸顶（9/11 修的背景 bug）**：`.tbl-scroll` **在所有视口都是滚动容器**（`overflow:auto` + `max-height:70vh`），表头 `position:sticky; top:0` 在**容器内**吸顶。原因：表格总宽 = 信息列合计 + 档位数×60 会超过 `.wrap` 的内容宽（上限 1280px），容器若不可滚，表格就会溢出容器，**容器的白底/边框/圆角只铺到容器宽度，右侧档位列透出页面底色**——这正是「字段变长后背景出问题」的根因。
    - **宽度预算**：内容宽上限 1280px（`.wrap` 1320 − 40 内边距）。按当前 1068px 信息列合计：**1–3 档的分组放得下、无需横滑；4/5/6 档分别需横滑 30/90/150px**（最宽的一组是美国空运 6 档）。
    - **加列/加档位时先算这笔账**：`信息列合计 + 档位数×60 + 2（边框）≤ 1280` 才不用横滑；超了就横滑（容器已兜住，不会再破底），但**不要**为了塞进来把列压到读不清。
    - 注：`--fb-h`（筛选栏高度，JS 在 `documentElement` 上设置）原本用于让表头吸在筛选栏下方，容器成为滚动容器后该用法失效；变量仍在设置、无副作用。
  - **卡片视图的 meta 行**：`来源 / 发布 / 时效 / 目的地 / 交货地 / 交货仓库 / [城市] / [开始邮编] / [结束邮编] / [重比]`——方括号内为**有值才显示**（与既有「重比」同处理，避免给 2900 多条空记录各挂 3 行空字段）。
- **与模板 Excel 的字段对照**：页面已把 Excel 的 `交货地`、`城市`、`开始邮编`、`结束邮编` 四列**显式呈现**（9/11 补齐；此前这 4 个字段数据里都有，但表格视图没输出、卡片视图又把 `交货地` 藏在 `交货仓库||交货地` 的兜底里、`城市`/邮编只作为 `目的地` 的兜底出现）。**注意口径差异**：Excel 的 `目的地` 是独立一列 `FBA仓库`，页面的 `目的地` 是 `FBA仓库 → 城市 → 邮编段` 的**兜底合并值**，所以有 24 条澳大利亚记录（商业地址区）页面的「目的地」显示城市名而 Excel 的 `FBA仓库` 列为空——这不是缺数据，是兜底显示。
- **筛选栏**：文件、来源表、国家、运输方式（干线/末端）、货型、包税、**邮编查询**、关键词，支持折叠
  - **布局（9/11 修）**：第 1 行 = 7 个下拉（`.frow` 宽屏下 `repeat(auto-fit,minmax(150px,1fr))` 正好 7 列、铺满无留白）；第 2 行 = **「邮编查询」+「关键词搜索」并排**，二者同处一个满宽容器 `.fitem.search`，内部用 `.pair` 两列网格（`minmax(150px,260px) 1fr`）——**不要把「邮编查询」放回 `.frow` 直接子级**，否则它会被挤到单独一行、右侧留白且把筛选栏顶高一行。手机端（≤640px）`.pair` 变单列堆叠。
  - **邮编查询（9/11 新增）**：输入客户邮编 → 只保留覆盖该邮编的区间记录。口径 = 解析端协议 **§5.9.3** 的闭区间判定 `int(开始邮编) ≤ int(客户邮编) ≤ int(结束邮编)`。**按位数识别国家**（5 位=美国、4 位=澳大利亚；位宽正源 = 解析端 `sheet_configs.ZIP_WIDTH`），**位数与该国不符则不命中**——否则 4 位澳洲邮编 `2000` 会落进美国的 `00000-39999`、造成跨国家误命中。输入框下方实时提示识别到的国家（如 `按「美国」5 位匹配邮编区间`），非 4/5 位会标红提示 `需 4 位或 5 位数字`；输入只保留数字、最多 5 位。
  - **注意该条件是「严格口径」**：它只留**按邮编分档**的记录（全库共 **60 条**：美国 36 + 澳大利亚 24）。**其余 2936 条属于「全国统一价、不按邮编分档」的表**，按协议「不参与邮编命中」会被一并过滤掉——所以输入一个美国邮编后，只剩 `美国空运` 与 `美森以星合德OA非OA海派` 两张表的记录。若希望「不分区间的表也一并列出」（它们其实覆盖全境），需另加一个开关。
- **长文本处理**：被两行截断的「渠道名称 / 目的地 / 时效」可点击弹气泡看全文；页面滚动或缩放时气泡自动收起
- 价格区间列在表格中均分剩余宽度，并设有最小可视宽度，避免手机端挤压重叠

## 更新流程

1. 用 fba-rate-parser 拆解新表 → 确认 → 导出页面数据
2. 重新生成 `fba-rate-query.html`，并复制为 `index.html`（GitHub Pages 根路径入口）
3. **在页面 JS 的 `PUBLISHED` 常量里，写入本次发布那张表的日期**（键为来源表名；纽约表名带尾空格，查表时已做 `trim`，写键可省略尾空格）——口径为**该表本次上线日**（即当天），人工维护、不会自动更新
4. `git add . && git commit -m "update: <说明>" && git push origin main`
5. GitHub Actions 自动部署，约 1-2 分钟生效

推送网络方案见 `DECISION_LOG.md`。
